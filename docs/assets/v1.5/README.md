# M300Boot 1.5 — native OLED renders

These 29 screens are generated by executing the matching C framebuffer renderer on a computer. They are not photographs, captured hardware output or evidence of a completed printer operation.

BOOT labels and menu layout are obtained from the actual native menu API. Installer labels and title are extracted from its current static menu declaration; confirmation wording is obtained by executing its pure input state machine. Hardware screens use three synthetic erased pages and show `Unavailable`, without a real serial number or counter. Remaining operation phases use deterministic illustrative inputs recorded in the manifest.

The original packed stock font and ring pixels are retained. Each framebuffer is converted directly from its native column-major 4-bit values to RGB cyan on black: `(0, level × 17, level × 17)`. Native PNGs are 256×64; the adjacent previews are exact 4× nearest-neighbour enlargements, 1024×256. No glyphs or version labels are painted over an older image.

[Render manifest](RENDER_MANIFEST.json) lists the source hashes, portable compiler commands, per-screen fixture and framebuffer/PNG hashes. [Validation](RENDER_VALIDATION.json) records native execution and PNG readback checks. Private firmware sources and compiled host libraries are excluded from the public repository.
